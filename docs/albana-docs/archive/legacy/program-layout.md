## 4. Landing Page: Section Program (Hal Sekilas)

### 4.1 Prinsip
- **Dua kartu berdampingan di desktop dan bertumpuk pada layar sempit**, bukan tab atau carousel.
- Setiap kartu memuat **hal sekilas** yang cukup untuk memutuskan "lanjut atau tidak", tanpa memuat detail.
- Tiga materi utama langsung terlihat; materi lainnya dibuka dengan disclosure **Lihat materi lainnya**.
- Setiap kartu memiliki **Daftar program** dan **Lihat selengkapnya**. Pendaftaran memakai batch aktif bila tersedia, atau mempertahankan identitas program sampai batch dibuka.
- **Tidak ada langkah cara daftar** di landing page (keputusan 4).

## 6. Halaman `/register`

**Alasan dipisah:** langkah pendaftaran, pembayaran, dan reschedule dikumpulkan di satu tempat dan **tidak diulang** di landing page atau halaman program.

### 6.1 Cara tiba di halaman
| Asal | Tautan |
|---|---|
| Kartu program (landing) | `/register?batch=<slug-batch>` bila aktif; `/register?program=<slug-program>` bila belum ada batch aktif |
| Halaman detail program | Tujuan yang sama dengan kartu program |
| Navbar dan footer | `/register` (tanpa pilihan; tampilkan daftar batch yang menerima pendaftaran) |

### 6.2 Isi halaman *[Draf]*
| Bagian | Isi |
|---|---|
| **Judul** | Daftar kelas |
| **Ringkasan batch** | Program, tanggal, jam, tempat, status (sama dengan kartu) |
| **Tautan kembali** | "← Kembali ke jadwal" |
| **Tombol** | "Buka formulir pendaftaran" (formulir yang dipakai klien; tab baru) |
| **Siapkan sebelum mengisi** | Nama lengkap, nomor WhatsApp aktif, batch pilihan |
| **Setelah formulir dikirim** | 1) Admin menghubungimu. 2) Admin mengirim nominal dan petunjuk pembayaran. 3) Setelah pembayaran diverifikasi, pendaftaran dikonfirmasi |

## 7. Solusi Navigasi di Next.js: Apakah Pindah Halaman Mengurangi UI/UX?

### 7.1 Jawaban singkat
**Tidak, bila navigasi dibuat dengan benar.** Next.js (App Router) memakai `<Link>` untuk **client-side transition**: halaman tidak dimuat ulang, **layout dan UI bersama dipertahankan**, dan hanya bagian yang berubah yang diganti. Next.js juga melakukan **prefetch** rute yang ada di viewport, dan **streaming** dengan `loading.tsx` untuk menampilkan kerangka saat konten dimuat. Pada praktiknya, pindah dari landing page ke `/program/[slug]` terasa seperti membuka panel baru dalam aplikasi yang sama.

Yang merusak pengalaman biasanya **kesalahan implementasi**, bukan perpindahan halaman itu sendiri.

### 7.2 Risiko dan solusi

| # | Risiko UX | Penyebab | Solusi |
|---|---|---|---|
| 1 | Layar berkedip dan lambat | Memakai `<a>` biasa atau `window.location` | Selalu pakai **`<Link>`** untuk tautan internal |
| 2 | Jeda saat membuka detail | Rute dinamis tanpa kerangka | Tambahkan **`loading.tsx`** (skeleton berbentuk sama dengan halaman) agar navigasi langsung terasa. Dokumentasi Next.js menyarankan ini untuk rute dinamis |
| 3 | Tidak ada prefetch penuh | Rute dinamis tidak di-prefetch penuh | Jadikan halaman program **statis (SSG/ISR)** dengan `generateStaticParams`, dan segarkan lewat revalidasi saat admin menyimpan |
| 4 | Pengunjung kehilangan konteks | Tidak jelas cara kembali | Tombol **"← Semua program"** yang menuju `/#program`, breadcrumb, dan dukungan tombol Back browser |
| 5 | Navigasi "berubah" tiap halaman | Navbar dan footer diulang di tiap halaman | Letakkan navbar, footer, dan bilah tombol ponsel di **layout bersama** (`app/layout.tsx`); layout tidak dirender ulang saat berpindah |
| 6 | Judul tertutup navbar sticky setelah anchor | Navbar menutup konten | CSS **`scroll-padding-top`** setara tinggi navbar (disarankan oleh dokumentasi Next.js) |
| 7 | Anchor `#jadwal` dari halaman lain gagal | Tautan relatif | Pakai `href="/#jadwal"` dan beri ID tetap pada section |
| 8 | Halaman melompat saat memuat | Gambar tanpa dimensi, skeleton beda bentuk | Tetapkan `width` dan `height` gambar, `next/image`, skeleton sama ukuran |
| 9 | Posisi gulir hilang saat Back | Konten dimuat ulang atau dirender sisi klien semua | Gunakan Server Components dan navigasi `<Link>`; uji tombol Back |
| 10 | Animasi berlebihan | Transisi lama | Fade singkat (±150–200 ms), hormati `prefers-reduced-motion`; transisi antar-halaman bawaan browser (View Transitions) hanya bila tersedia di versi yang dipakai (**verifikasi**) |
| 11 | Koneksi lambat | Rute berat | Skeleton, ukuran gambar kecil, `error.tsx` dengan tombol **"Coba lagi"** |
| 12 | Fokus keyboard tersesat | Halaman berganti tanpa fokus | Pindahkan fokus ke judul halaman (`h1`) atau tautan lompat ke konten; `aria-current="page"` pada navigasi |

### 7.3 Pilihan pola

| Pola | Cara | Cocok? |
|---|---|---|
| **Halaman terpisah dengan `<Link>` (disarankan)** | `/` → `/program/[slug]` → `/register` | Ya: sederhana, bisa dibagikan, bagus untuk SEO |
| **Intercepting route (modal)** | Detail terbuka sebagai panel di atas landing page, URL tetap `/program/[slug]`, kunjungan langsung menampilkan halaman penuh | Opsional untuk fase 2. Konteks landing terjaga, tetapi lebih rumit; panel berisi 12 materi, jadwal, dan sertifikasi akan terlalu berat |
| **Accordion di landing page** | Detail dibuka di tempat | **Tidak disarankan** untuk detail panjang; memanjangkan landing page dan menyulitkan pelacakan |

### 7.4 Rekomendasi
1. Halaman terpisah dengan **`<Link>`**, layout bersama, `loading.tsx`, dan **SSG/ISR** untuk `/program/[slug]`.
2. Tombol **"← Semua program"** ke `/#program` dan `scroll-padding-top`.
3. **Bilah tombol "Daftar"** tetap di ponsel, di layout bersama, sehingga aksi utama tidak hilang saat berpindah halaman.
4. Setiap kartu di landing page **mem-prefetch** halaman detailnya karena tautan masuk viewport.
5. **Pengujian UX** sebelum rilis (Bagian 10).

### 7.5 Dampak ke `tech.md`
| Item | Tindakan |
|---|---|
| Rute | Tambah `/program/[slug]` dan `/register` |
| Berkas | `app/program/[slug]/page.tsx`, `loading.tsx`, `error.tsx`, `app/register/page.tsx` |
| Pembuatan statis | `generateStaticParams` untuk slug program; revalidasi saat admin menyimpan batch atau program |
| CSS | `scroll-padding-top` pada `html` |
| Layout | Navbar, footer, dan bilah ponsel hanya di `app/layout.tsx` |
